Capabilities

One acquisition stack, two front ends.

A general-purpose crawler and a search-results pipeline share the same workers, proxy pool, rate limiter, block detection and storage.

Crawl any website

Start URLs, scoped link following, robots.txt and crawl-delay obeyed by default. Extracts metadata, headings, OpenGraph, JSON-LD, text and links, plus per-site CSS-selector fields and item lists.

cmd/crawlrobots.txtJSON-LD

Search results pipeline

Structured organic results, featured snippets, "people also ask" and AI Overviews, direct or through a SERP API provider, with drift detection when page layouts stop matching.

cmd/harvesterdrift detection

Health-tracked proxy pool

Round-robin, random or success-weighted rotation, escalating cooldowns, live reload that keeps health history, and any HTTP(S) proxy provider.

Adaptive rate limiting

Per-proxy and per-host token buckets that slow down on pressure and honour Retry-After exactly.

Blocks detected, never bypassed

CAPTCHAs, challenges, consent walls and rate limits are classified and routed around by cooling the proxy, not evaded.

Plain HTTP or headless Chromium, with failover

Fetch with Go's HTTP client, render with Playwright, or run hybrid: start fast over HTTP and fail over to a real browser only where a page needs it.

HTTPPlaywrighthybridSERP API providers

Production plumbing

Redis Streams queue, PostgreSQL or JSON Lines, Prometheus and Grafana, Docker Compose and systemd.

Proxy provider measurement

Know how a proxy provider behaves before you depend on it.

The repository includes a small, auditable runner that measures a residential or mobile provider the way a scraper experiences it, and a protocol for turning that into a defensible report.

  • Confidence intervals, not single numbers. Small samples are flagged rather than over-read.
  • Usable results, not just HTTP 200. A challenge or consent page counts as a failure.
  • Billed bytes reconciled against the provider's own usage figures.
  • Sensitive data stays private. Exit IPs are hashed and credentials are redacted; only selected aggregate findings are published.

Read the measurement protocol →

Does rotating really rotate?
A fresh tunnel per request, because reused tunnels keep their exit IP; reuse is recorded.
Do sticky sessions hold?
Exit IPs per session, and a cap on requests per session.
Is state targeting accurate?
Location read from the measured request itself, across all 50 states plus D.C.
Why did requests fail?
Provider error codes captured, separated from timeouts and target responses.
Do retries recover?
First-attempt against eventual success, recovery time, bytes spent on failures.
What does it cost?
Every byte exchanged, compared with what the provider bills.
